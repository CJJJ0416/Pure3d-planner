# 多帧点云与 Tomography 监督审查

> 历史记录。2026-11-06 已切换为原生 VST 标签可用性监督，文中的三重筛选、旧验证与旧 v1 入口已删除。当前代码见 [原生监督清理](TEACHER_SUPERVISION_CLEANUP.md)。

2026-11-06，本地新生成侧边斜坡平台 seed 20261106。平台 3.9 × 4.2 m，高 1.1 m，右侧坡道宽 1.5 m，坡顶经过转弯平台连接主平台。81 帧、每帧 1000 条 MID-360 方向表射线，共 21,637 个有效回波。采集使用现有 WarpMid360 的 CUDA mesh_query_ray，不启动 Isaac/Kit。绘图使用 CPU matplotlib。

## 确认的问题

### 1. VST 顶层在导出时缺失

原始构建设置了 3 个 slice，但上游简化最终保留 [0,1]，丢掉包含 1.1 m 平台的顶层。原 VST 地面最高 1.0 m，平台顶面 10,534 个回波均没有匹配的原生地面。81 帧中 54 帧没有 cost 监督。

修复位于 `src/stair_nav/planning/vst.py::build_tomogram`：多分配一个顶部哨兵 slice，供上游的倒数第二层保留规则使用。上游 VST 源码及来源指纹保持原样。修复前后使用完全相同的 terrain.obj、terrain.pcd、81 帧位姿和射线。旧地图与旧标签保留用于对照。

| 项目 | 原始地图 | 补足顶层后 |
| --- | ---: | ---: |
| 原生查表有 cost 的回波 | 10,297 | 21,637 |
| 平台顶面有匹配地面的回波 | 0 / 10,534 | 10,534 / 10,534 |
| 平台顶面落入 cost 监督格的回波 | 0 | 9,804 |
| 累计 cost 监督格，按帧计数 | 889 | 7,582 |
| 没有 cost 监督的帧 | 54 / 81 | 0 / 81 |

### 2. cost=60 仍被监督条件排除

在补足顶层后的同一批数据上，四个条件的 cost=60 累计帧格数依次为：

| 条件 | cost=60 累计帧格数 |
| --- | ---: |
| Tomography 标签已知 | 24,705 |
| 再要求 3×3 地面高度连续 | 628 |
| 再要求当前帧匹配的地表回波 | 0 |
| 再要求射线覆盖 | 0 |

离线只去掉 cost 分支的高度连续条件，仍保留已知标签、匹配回波、射线覆盖，可得到 280 个 cost=60 帧格，全部 cost 监督格 7,914，其中 cost≥50 为 670。正式原定义只有 7,582 格、cost≥50 为 379。此项仅为诊断统计，没有修改训练掩码。

已知标签并不意味着当前帧看到了该位置，因此不能以 24,705 为可监督点数量。280 的对照才隔离了高度连续条件对当前可观测边界的影响。

### 3. 坐标、查表与栅格重采样

新增 `data/tomography_pairs.py::query_world_point_costs`，使用原始点的世界 XY 直接查原生 VST，选与点 Z 最接近的已知地面层。同高重复表示取最小 cost。未知保留 NaN，保留所有原始点，不用训练掩码筛除。竖直面可以携带其柱的 cost 用于展示，但 `surface_match` 单独记录是否为贴地表回波。

训练用的局部 GT 来自 `lidar_reference_pairs.py`，不是 v1 的 yaw-only 机身网格。审查保持原始 LiDAR 完整姿态，逐帧重建正式 v2 标签后与已保存标签比较。

- 保存与重新生成的 cost、可用性及掩码差异均为 0。
- 直接检查存储 source_layer/source_grid_xy 的 cost 差异为 0。
- 7,467 个同原生单元且同地面高度的共同回波，cost MAE 为 0。
- 点端直接查表与局部格心 GT 在 15,740 个共同点上的 MAE 为 1.799，最大 60。前者查询真实端点，后者查询局部格心，边缘可能落入不同源单元。这两种采样位置不能不加区分地作为同一个 GT。
- 最大 sensor/world 坐标往返误差约 2.38e-7 m。

该对比检查标签生成链的一致性。参考 cost 本身仍来自 VST，不能独立证明 VST 的物理通行代价正确。平台顶面缺失则有解析几何、实际射线命中及原生高度缺失三方证据。

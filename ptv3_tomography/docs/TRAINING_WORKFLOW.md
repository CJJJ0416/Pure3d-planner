## 1. 训练主线

```text
场景、传感器、坐标与建筑划分定版
    ↓
多建筑 × 多路线 × 多视角：采集原始点云、射线、时间与位姿
    ↓
离线 Tomography + 局部标签对齐 + 各任务独立监督掩码
    ↓
少量数据检查 → 单批训练检查 → 未见建筑感知验证
    ↓
单帧 PTv3 + cost/高度辅助解码头预训练
    ↓
保存 checkpoint，冻结 PTv3
    ↓
当前帧特征 + 相对雷达 odom / 时间差 / 目标与状态
    ↓
特征适配 → SRU → Actor/Critic
    ↓
在线 LiDAR 接入 M0 → BC → DAgger → PPO/PGCL
    ↓
仅终点评估：保留路线、未见路线、未见建筑分别报告
```

先完成单帧 PTv3 + SRU 可运行基线；额外历史 Attention 或地图接口作为后续独立对照。

## 3. 固定数据契约

### 3.1 坐标、时间和模型边界

- 点云原始坐标采用各帧传感器系；每帧同步雷达自身在统一 odom 系中的位姿与时间。融合以当前雷达为参考，使用窗口相对位姿和时间编码；不重复乘机身外参。当前 D1 v1 标签的机身重力/yaw 系是原契约，须先完成 D1-R0 迁移。
- 明确 odom 是机身还是传感器位姿；地面支撑高度、机身高度、雷达安装高度分别记录。
- 保存干净位姿用于标签对齐；模型读取相对位姿及时间。位姿误差实验分别记录干净和退化估计，不修改几何标签来迎合错误估计。
- PTv3/历史融合只接收当前及过去的传感器观测。绝对世界位置、建筑 ID、完整地图和未来路线不进入 Actor。
- 相对目标 XYZ、自状态和上一动作在导航分支加入。更换目标不改变物理地图标签。
- 当前层可作为读取的重点，其他有效层仍保留。`slice_h0/slice_dh` 与简化层编号不能直接替代实际地面高度。

### 3.2 资产与划分

- 按建筑 seed/谱系划分 train/dev/test；同楼的路线、相邻帧和障碍变体保持同组。最终 test 不用于调参或挑 checkpoint。
- 新监督资产约定障碍代价为 60，记录生成配置；旧的 50 代价资产保留原记录，进入统一训练集前重新生成或单独分组，不直接缩放后假称等价。
- 代价归一化采用固定、版本化尺度，不逐帧或逐场景 min-max。监督代价尺度与导航奖励系数分别管理。
- 锁定几何、传感器扫描表、Tomography 配置、代码提交与工作区差异指纹。相同场景多路线共用一份教师资产。

产物：数据 spec、建筑分组 manifest、传感器配置、标签版本、资产指纹。D1 已实现单场景 `dataset_spec.json`、连续窗口 `manifest.json` 和配对 CLI；跨建筑划分尚待 D3。

## 4. 小规模批量采集

### 4.1 首批检查与扩展

1. 用平地、坡道平台、桥/孔洞等少量明确几何检查数据对齐；这些场景用于诊断，不用于声称泛化。
2. 在同一建筑批量生成不同起终点路线，反向采集，增加转身、停留、侧看和适度偏离中心线的位姿。
3. 保存每条路线与全部采样时间，按时间切连续窗口。不要使用网页播放进度或截图作为数据。
4. 首批链路正常后再增加建筑与几何组合，单独保留未见建筑验证。

首轮传感器使用 `10 Hz`；导航训练可将连续多帧组织为 SRU 有序序列。在线每一步只编码当前帧并携带上一状态。现有 K=8 数据包及其历史覆盖掩码属于旧备选，不自动作为单帧 PTv3 的监督掩码。

### 4.2 每帧必须保存什么

| 类别 | 必要内容 |
| --- | --- |
| 身份 | scene/lineage、路线与 episode ID、帧号、数据版本 |
| 时间与运动 | 时间戳、参考点位姿、传感器外参、相对运动 |
| 原始观测 | 显示截断前的点、射线方向/原点、距离、有效命中及缺测原因 |
| 扫描假设 | 瞬时/滚动扫描、扫描表索引、近远界、噪声和退化参数 |
| 标签定位 | 局部参考变换、水平网格、源切片、实际地面/顶面高度及来源 |
| 监督 | cost/support/height 与独立掩码、覆盖信息、标签可靠性状态 |

网页当前每扫描采样约 3000 条射线，返回散点最多 1000 个显示点；这些是预览设置。离线导出保存显示截断前的数据，再定义训练采样策略。当前模拟是瞬时 mesh 首次命中；未实现的滚动畸变、反射率和自遮挡不写成已包含。

小样本对齐可以复用 CPU 预览射线；正式批量采集和在线训练采用 GPU 批处理。训练用 GPU LiDAR 是待接入项，不能用现有 GPU M0 或深度渲染替代其完成状态。

产物：可重复采集的序列分片、采集 manifest、失败日志、少量叠加可视化。所有路线独立保存，不受网页当前路线槽位替换影响。

## 5. 标签暂不可靠时怎样推进

### 5.1 几何真值与监督掩码分开

完整几何可离线生成支撑候选；射线与历史覆盖决定当前窗口能否监督该标签。原始 `valid_ground` 只表示有有效地面记录，不直接代表指定高度处存在可行走支撑。

每个标签通道独立记录：`verified`、`provisional` 或 `unknown`，以及 `mask_cost/mask_support/mask_height`。第一版只用 `verified` 标签优化；保留其他数据供后续重标，无需重新采集全部点云。

| 情况 | 处理 |
| --- | --- |
| 当前或历史观测充分，地面及代价对应关系明确 | 开启相应监督 |
| 明确实体障碍，高代价且支撑仍存在 | 保留高代价负例；支撑不因高代价自动变为 0 |
| 指定高度确认为悬空，且观测依据充分 | cost=60、support=0；高度不回归 |
| 支撑归属尚不确定 | 关闭支撑监督；若连代价归属也不确定，同时关闭对应代价监督 |
| 整个窗口始终遮挡或只是无回波 | 保留未知，不能填成安全、无支撑或高度 0 |
| 骨架/膨胀代价依赖不可见的窗口外结构 | 屏蔽相关监督或单独统计，不能要求局部输入精确恢复隐藏全局布局 |

不使用只返回低代价层的奖励查询函数生成监督集，以免丢掉障碍负例。奖励里的 `None→0` 也不能作为感知安全标签。

### 5.2 当前可以启动的训练

- 先用已核对区域的代价和实际地面高度，跑通数据加载、前向、反向、保存与恢复。
- 尚无可靠支撑标签时，支撑损失关闭或掩码为 0，明确记录 `support_not_trained`。此时支撑头输出不能被称为支撑概率，也不供策略作确定证据。
- 边缘、孔洞、上下重叠楼面组成一小组独立几何诊断样本，逐项补齐可靠支撑标签，再启用支撑头。
- `has_support` 与机器人动态可通过性分开。支撑面积/高度变化、净空、坡度和连通关系分别检查，不能只靠一个二值位声称足式稳定。

这允许先推进工程链路。若进入导航时支撑头仍未验证，则 A 的接口采用明确缺少该通道的版本；相关 A/B 对照使用同一份实际 checkpoint，不宣称验证了“代价+支撑”完整方案。

标签检查优先覆盖：平台内部/外侧、同 XY 上下层、桥面/桥下、孔洞边缘、侧看坡道、当前缺测但历史曾见、全程遮挡。输出成本图、实际高度、支撑/可靠性与掩码的独立叠加图；不能只看彩色 costmap。

## 6. 共同感知预训练

模型：当前帧 PTv3 → 带坐标的空间特征 F_t → cost/高度辅助解码头。用当前帧可观测单元的掩码训练；目标网格参考系先完成 D1-R0 统一。P1-T1微型配置已锁定官方PTv3两级编码/一级解码，输出16通道空间token；三帧去重后为210/182/200个token。正式模型规模另行选择。

完成单帧数据与坐标检查后训练该前端。SRU 导航训练单独使用有序序列，避免用包含历史观测的标签掩码监督只看当前帧的前端。

损失采用独立有效掩码的代价 Huber、支撑 BCE、支撑高度 Huber，各自按有效单元数归一化。先索引有效项再计算，避免 NaN 高度与零掩码相乘后污染 loss。某任务无有效单元就跳过该任务并记录；整批无监督则不更新。

推荐顺序：

1. 单批样本检查：坐标/标签相同、输出有限、启用分支有梯度；少量样本能拟合用于证明链路工作。
2. 小规模多建筑训练：监控 train/dev 分组指标，选择感知配置。
3. 增加采样和位姿退化；先分别测试，再考虑组合，记录退化强度。
4. 在导航阶段检验 SRU 的时序记忆；额外历史 Attention 仅作为独立消融候选。

检查点保存：模型结构、全部权重、优化器、随机状态、数据/划分/标签版本、预处理、采样窗口、归一化、坐标与层定义、依赖和性能测量配置。

冻结依据：未见建筑分组指标可复现，明显的跨层借支撑/未知填安全错误已解决，延迟与显存可满足拟定导航周期。损失下降或单场景拟合不能单独作为冻结依据。阈值在小规模验证后写入配置，不预填尚无依据的精度目标。

## 7. 冻结和在线传感器

| 项目 | 当前主线 |
| --- | --- |
| 冻结 | 预训练的单帧 PTv3 |
| 地图解码头 | 预训练使用，导航可关闭或仅用于诊断 |
| 可训练模块 | F 的空间适配、状态融合、SRU、Actor/Critic |
| 每步输入 | 当前点云、相对雷达 odom、时间差、目标和自身状态 |

- 冻结参数并保持归一化统计不变；预训练 dropout 使用推理模式。验证导航更新前后冻结 state_dict 一致。
- SRU h/c 属于运行时状态，各并行环境独立管理；真实 episode 结束后清空，同 episode 的换子目标和换层不清空。
- 在线点云必须来自学生实际执行后的位姿。网页参考路径回放只用于感知数据，不能作为 PPO 的学生观测。
- 离线与在线采用同一坐标、扫描与预处理契约；先在相同位姿对比两条链路，再检查完整导航延迟。
- Actor 使用实时传感器和状态；Tomography 真值只用于离线监督。Critic 若保留现有特权输入，应按现有任务约定处理。
- 先确认 PTv3 实现与现有 `torch==2.7.0+cu128` 环境的兼容路线；可独立预训练，但上线前必须在最终环境核对 checkpoint 加载与前向一致性。冻结权重不解决依赖或特征形状不兼容。

## 8. 导航训练顺序

1. **教师采集与 BC：**复用完整 VST/GPMP 路径教师；示范按当前物理执行标准验收。新导航输入需要重新采集相应传感器序列与状态，不能假定旧深度 BC 缓存可直接使用。
2. **DAgger：**学生到达的实际状态生成观测，教师给纠偏标签。感知离线数据可补充这些偏离路线的视角；若重训前端，则另起感知版本并重新核对冻结接口。
3. **PPO/PGCL：**从短局部任务到完整结构，再逐步减少提示、增加路线长度。一次只改变一个主要课程变量，保留既有任务采样与能力约定。
4. **仅终点任务：**从 episode 开始只给终点，单独评价寻找入口、上下楼、绕障与回退；不把有提示跟路成功当作长程导航成功。

导航对照基于同一选定 run 的 resolved 契约：教师由完整路径和实际状态决定，不能随 PGCL 提示密度改变标签；保留物理速度/加速度/延迟限制、倒车横移能力、到达终点无需刹停的已接受任务定义。感知辅助损失不自动变成奖励，不恢复旧额外惩罚。具体基础奖励开关和数值从该 run 读取，不从历史示例复制。

循环更新保持时间顺序、padding/reset mask 和正确初态；只在真实 episode 结束时清 h/c。记录 terminated/truncated，超时价值估计使用重置前终态。SRU 序列不跨 episode 拼接，在线保持状态时每次只推进新帧。

接入若影响训练执行、课程或奖励，复验现有选层等价性（含 None→0）、同状态八级提示教师标签、安全探测完整恢复，以及密集/仅终点 GPU 完整路线。已有检查的历史通过记录不能替代本次接入验证。具体脚本见 [完整路径教师约定](../../../isaac_training/docs/training/full-route-teacher-plan.md)。

| 历史融合能补充观测 | 单帧 PTv3 vs K 帧融合 | 历史曾见遮挡区域的代价/高度误差、支撑漏判与误判 | 待实现 |
| A/B 哪种接口更合适 | 同一感知 checkpoint 的 A vs B | 相同建筑划分、任务、教师、奖励、导航预算；成功/接触/失去支撑及完整耗时 | 待实现 |
| 几何辅助监督改善导航 | 同输入、同初始化与预算，有/无辅助预训练 | 独立导航运行；在需要主张该收益时加入 | 后续对照 |
| 能用于未见建筑 | 锁定模型后的独立建筑测试 | 仅终点，绕障/上楼/下楼/长路线分项 | 待实现 |
| 能承受传感器退化 | 干净 vs 缺测/位姿误差/延迟 | 成功、接触、支撑误判，注明强度 | 基线稳定后 |

首轮不跑所有组合。先完成一个模型的完整感知→导航链路，再进行单帧/多帧与 A/B 对照。若与既有深度 SRU 比较，说明传感器与前端均变化，该比较不单独归因于历史 Attention。

感知指标：各任务有效监督数量与比例；cost MAE；height MAE（有效支撑）；支撑 precision/recall；无支撑预测成有支撑的比例；已知危险区域预测成低代价的比例。未知区域单独报告覆盖与错误自信，不填进安全标签准确率。

导航指标：完整终点成功率、原始机身接触、失去支撑/跌落、超时/卡住、上下楼分项、长路线完成情况。保留父路线作为统计单位，不能把同路线多个窗口当成独立建筑样本。

计算指标：传感器生成、点云预处理、PTv3、历史融合、A 的地图解码/CNN或 B 的适配、策略、完整循环的延迟与显存。报告硬件、batch、点数、历史长度和精度；测 GPU 延迟要同步。比较预先登记的同一组路线，并报告不同训练 seed 的波动；训练 seed 数量按预算预先锁定。

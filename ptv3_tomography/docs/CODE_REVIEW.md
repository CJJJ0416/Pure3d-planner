## 发现与处理

| 优先级 | 发现 | 影响 | 处理 |
| --- | --- | --- | --- |
| P1 | 官方源码同时位于 `third_party/ptv3_official` 与 `third_party/PointTransformerV3` | 导入路径可选中不同副本，服务器难以固定版本 | 验证46份官方文件SHA256一致后，保留用户指定仓库，清除重复副本；记录固定提交和文件指纹 |
| P1 | v2 manifest中的扫描路径、spec中的场景路径为本机绝对路径 | 数据复制到服务器后loader/几何验收失败 | loader按数据包解析相对路径；新增校验复制工具，将raw/标签/odom/场景汇集为自包含包；历史路径只作provenance |
| P1 | 审查时只有官方骨干探针和数据检查，没有完整PTv3监督训练器/解码头/checkpoint/SRU接入 | 不能把一次骨干前向反向当成全训练链路已经跑通 | 明确列为尚未完成的P1；本次不伪造训练入口或训练结果 |
| P2 | 几何辅助函数从可执行验收脚本导入，且入口固定依赖 `isaac_training/src` | 目录移动、服务器独立运行时导入断裂 | 拆为纯NumPy的 `geometry.py`，独立 `ptv3_tomography` 包和项目根定位 |
| P2 | 小检查启动器在import时直接exec新进程 | 导入/审查工具可能意外启动检查 | 新入口使用main保护；默认CPU、2GiB硬限制与单线程保持不变 |
| P2 | 序列长度仅取数据spec的8，无法按本地2步预算展开 | 小预算配置与实际SRU输入长度不一致 | 有序loader支持显式unroll_steps=2，按episode重新分非重叠块；不影响当前帧标签掩码 |
| P2 | 减点函数凭数组首维等于射线数推断字段 | 极小4射线数据会误改4×4位姿矩阵 | 仅对明确列出的逐射线字段减点；位姿保持4×4原值 |
| P2 | 文件指纹用read_bytes一次读入整个资产；报告直接write_text | 大资产可能造成RAM峰值；中断时留下空/半JSON | 新公共IO以1MiB块hash；新报告同目录临时文件+原子replace |

## 保持的数据语义

雷达odom直接描述雷达，不重复乘机身外参；输出完整雷达坐标，物理高度由重力投影定义。单帧前端只使用对应当前帧监督，不能套用K=8历史掩码。支撑全部unknown且损失关闭。掩码依赖观测预算，减点和裁图后重新计算。旧v1/v2原始数据及其指纹快照保留。

官方提交：`4e277e6802eb3a6299fd71f707394d918b96f5fc`，软件包版本0.1.2，要求torch>=2.10。官方源码及LICENSE/NOTICE保留原样；仅在 `src/ptv3_tomography` 增加项目适配。

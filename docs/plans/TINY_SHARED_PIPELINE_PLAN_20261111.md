## 1. 已确认的方向

先统一使用官方 `utonia_tiny` 公共编码器，跑通完整链，再考虑扩大模型参数量。暂停 Small、模型规模对照和新的楼梯专项微调。

```text
rough PCD
  → Tiny 公共编码器
  → Filter
  → Recon：修复点云及可查询特征 H(q)
  → Adapter → FiLM → CostHead
  → XYZ + trav_cost
  → 当前 DC A* → GPMP
```

- Tiny 全程冻结，保持 `eval()`。每个输入窗口只执行一次公共编码。
- Filter、Recon、Cost 分阶段训练，完成一阶段后冻结，再训练下一阶段。
- 现有独立 Cost 模型及权重保留为参考，不直接视为新共享链的可用权重。
- 本轮 Recon 使用完整 Mesh GT。Seen2Scene 离线蒸馏后续接入，不作为首轮闭环的依赖。
- 公共底座冻结后，任务头分别适配同一特征空间。不在 Cost 阶段单独解冻公共编码器。
- “参数量和训练不足”是待验证的原因，不能用单场景拟合成功代替多场景泛化证据。

## 3. 数据与特征契约

### 公共编码

- 编码器：官方 `utonia_tiny`，上采样特征486维。
- 沿用 Filter 的 `scale=0.5、grid_size=0.01`，物理体素2 cm。
- 核心窗口4×4×3 m，外扩1 m上下文。
- 坐标保持地图原点下的米制 XYZ。局部变换、inverse 和原始点索引随特征传递。
- Tiny 权重和缓冲量不更新。修改编码器、预处理或上游任务头后，相关缓存需要重新生成。

### 随机数据

- 复用 WFC 建筑生成器，随机化布局、面积、楼层高度、楼梯位置与类型、阶高、踏深、宽度、栏杆、斜坡和开口。
- 每个 seed 保存实际几何参数及 overview。
- 从同一完整建筑生成 rough 变体，包含缺失片区、噪声、行人和杂波。
- 完整 Mesh、rough PCD、过滤标签及重建目标通过实例和点索引关联。
- train/val/test 按完整建筑及其派生变体划分。同一建筑的旋转、缺损和杂波变体不跨划分。
- 场景旋转、平移及镜像在教师计算前完成。不在线旋转点云后沿用旧 VST 标签。

### 模块接口

| 环节 | 输出 |
|---|---|
| 公共编码 | 原始 XYZ、体素特征、inverse、窗口变换 |
| Filter | keep_score、保留索引、XYZ_keep、F_keep |
| Recon | repaired XYZ、observed/generated 来源、`query_features(q) → H(q)[Q,128]` |
| Cost | `H(q) → 256维适配 → FiLM → cost[Q,K]` |

Recon 新增点由自身查询场提供特征，不重新调用 Tiny，不借用 GT 特征。H(q) 同时支持训练时的 Tomogram 查询与部署时所有修复点查询，不只覆盖已导出的生成点。

## 4. 待实施的分阶段训练

新增统一的 headless 流水线入口，调用各模块独立的数据、训练、评估和推理接口。支持单阶段运行及从对应 `last.pt` 恢复。

### F：过滤

- 复用已有 FilterHead 和五组均衡 SmoothL1 损失。
- 仅训练 FilterHead，使用验证集选择过滤阈值。
- 导出实际预测的保留点及共享特征，供 Recon 使用。

### R：重建

- 按现有 SurfaceDecoder 设计实现空间特征场、表面概率及单元内位置偏移。
- 输入冻结 Filter 的实际输出，完整 Mesh 只提供监督。
- 使用表面分类、单元位置和局部平面损失。
- 保留输入点原始坐标，追加预测生成点。
- 训练可使用既定父单元展开课程，验证和部署完全由预测展开。
- 首轮使用现有设计允许的3 cm叶单元版本，完成后再评估1.5 cm版本。

### C：条件化代价

- 冻结 Tiny、Filter、Recon，只训练 Adapter、FiLM、CostHead。
- 在原生 Tomogram XYZ 查询实际 Recon 特征，监督为原生 `cost/50`。
- 学生参数顺序固定为 `[clearance_min,slope_max,step_max,stand_ratio]`。
- 教师保留完整原生规则，固定 `interval_free=0.5、p=2、cost_barrier=50`。
- 复用两套条件库，每套40个条件槽，包含固定基准和四参数单轴扫描。另一套采用随机背景条件。
- 保留全部原生有效监督。设施与背景均衡，条件变化区和稳定区均衡，四参数等权。
- 主损失为 `L_absolute + 2L_condition`，SmoothL1 的 β为0.1，变化阈值为0.02。

保留三个 Tiny FiLM 对照配置：完整方案、关闭条件差值损失、参数拼接替代 FiLM。正式长训练及消融在完整链通过后安排。首轮仅验证配置可执行。

## 7. 新增方向：重力参考与支撑表面判别

补充日期：2026-11-12。用户提出引入重力信息，区分地面与天花板，改善代价预测和 A*。本节为设计建议，尚未实现或测速，继续保持只归档的执行边界。

### 重力表示

重力使用地图坐标中的单位反重力方向 `u=-g/||g||`。地图已对齐重力时，`u=[0,0,1]`。不依赖地图Z零点，不按绝对高度将点划成地面或天花板。

对方向已可靠确定的单位表面法向 `n`，定义 `s_up=n·u`。朝向上侧的水平表面接近1，朝下的水平表面接近-1，竖直表面接近0。坡面随倾角连续变化。该量是几何特征，不是第五项机器人能力参数。FiLM的四参数顺序保持。

PCA局部法向自身具有正负号歧义，将所有法向翻到朝上会丢失顶面与底面的区别。当前DC法向针对实测占用体素壳定向，该壳会在薄表面两侧生成边界，不能直接把它等同于真实建筑朝向自由空间的法向。

### 当前代码依据

- 规划器已有 `gravity_up`，端点和新增跨阶边使用朝上法向条件，GPMP使用反重力参考。
- 来源点的上方占用探测目前只限定新增跨阶边。
- 原始DC三角图仍只按cost剪枝，没有对全部搜索节点统一应用支撑表面判别。
- 独立Cost模型没有显式的重力方向输入。其Tomogram监督主要位于支撑查询点，不能认为完整PCD上的天花板和立面也已经接受同等监督。

### 建议接入方式

- 公共Tiny保持冻结。重力信息和局部几何关系在Recon/Cost的任务模块中使用，不改变公共Tiny预训练输入契约。
- 以同一重力参考组织邻点相对高度、表面倾角和表面朝向。只有方向可靠的法向才解释有符号的 `n·u`。
- 增加与机器人条件分离的支撑候选判别分支，由完整Mesh的真实表面侧向和结构信息监督。该分支判断是否属于可作为行走候选的上侧表面，不等同于当前机器人一定能够通行。
- 原生VST代价监督、0–1尺度及四参数FiLM保留。没有Tomogram对应标签的表面不通过最近踏面回填来制造GT代价。
- 候选输出为 `XYZ + trav_cost + support_score`。A*结合支撑候选和现有cost limit选择节点，代价本身继续表达机器人条件下的通行难度。
- 保留上下层各自的支撑表面，不取全局最高或最低层。限定支撑面后仍保留现有机器人跨阶连接，避免删掉立面又误以为上下踏面已经相连。
- 顶面与底面的判别结果须回映到真实输入点及DC来源体素，避免将占用壳生成的另一侧误认为可行走楼层。

### 后续验证场景

同一楼板的顶面和底面、重叠楼层、楼梯与立面、连续斜坡，以及整体平移后的同一场景。分别检查支撑面误选、天花板进入搜索图的比例、踏步连通性、代价误差及A*路线。增加重力约束是否有效，以这些对照为准。

参考：[PCL法向估计说明](https://pointclouds.org/documentation/tutorials/normal_estimation.html)，其中说明局部PCA法向的符号歧义，以及多视点点云不能直接套用单视点定向。
